# スマホセンサー・コントローラー PoC

机の上でスマホを短く動かすことが、ゲームの入力として成立するかを試すための2つの実験です。

- **かたちを、はめる**: 手のカーソルを図形へ動かし、スマホの着地で「にぎる／離す」を交互に切り替えます。にぎると近くの図形をつかみ、次の着地で離します。方向・移動量がだいたい合えば同じ形の穴に吸着。好きな順に3つ置くと完了。
- **いろを、ふきとる**: スマホをホワイトボードクリーナーのように動かして、横長の単色ステージを消します。95%で完了。

ゲーム画面は表示・モード選択・リセット・診断のみ。マウス、キーボード、タッチで図形やクリーナーは動きません。スマホ画面には接続・校正状況、入力パラメータ調整、センサー値の診断を表示し、ゲームの状態は送りません。操作用スマホは1ルーム1台です。


## Dotへゲーム実績を届ける

Workersの `/mcp` はMCP Streamable HTTPとMCP Events (`2026-07-28`) を提供します。`/api/game-events` がゲーム側の送信先です。ゲーム画面上部の **「イベント送信」** タブにサンプルJSONが入り、編集・送信できます。`cursor` はサーバー側で採番します。

このPoCではイベントを最大100件、購読を最大24時間Durable Objectへ保存します。イベント送信後、条件が合う有効な購読先へ署名付きHTTPS webhookを送り、失敗時は一時エラーに限り再試行します。認証はありません。ゲームイベントはひとつの公開イベントストリームを共有するため、URLを知るクライアントはイベントを送信でき、MCPツールから最近のイベントを読めます。送信は全体で毎分60件までです。MCPイベントの購読先は `chatgpt.com` / `openai.com` のHTTPSホストに限定します。

### クラウド版Workに登録する

ローカルのマーケットプレイスへのインストールだけでは、クラウド版Workへの登録は完了しません。公開WorkerをChatGPTのカスタムMCPサーバーとして接続します。

1. 利用するアカウント・ワークスペースで [ChatGPT Plugins](https://chatgpt.com/plugins) を開き、`＋` → **Add custom MCP server** を選びます。
2. 名前を **ゲーム実績イベント**、Server URLを `https://phone-sensor-controller-poc.gyu-don.workers.dev/mcp`、Authenticationを **No authentication** に設定して作成します。
3. 既存の **カスタムイベントPoC** が同じURLに接続されている場合は、その接続を **Refresh** して利用します。
4. プラグイン詳細で `get_recent_game_events` に加え、イベント `achievement.unlocked` が検出されていることを確認し、インストールします。
5. 新しいWorkチャット（デスクトップではCloud）でそのプラグインを選び、「achievement.unlockedを購読して、届いたら達成内容に合わせてほめて」と依頼します。
6. 購読成立後にゲーム画面のイベント送信タブから送信します。再送テストでは `eventId` を変更してください。同じIDは重複として配信されません。

購読は通常のMCPツールとは別のイベント機能です。ツール一覧だけで購読可否を判断せず、イベント一覧と実際の購読・受信を確認してください。

公式手順: [接続・更新](https://developers.openai.com/plugins/deploy/connect-chatgpt)、[MCP Events](https://developers.openai.com/plugins/build/mcp-events)。

### ローカル版Work・Codexに追加する

`plugins/dots-game-achievements/mcp.json` は本番Workerの `https://phone-sensor-controller-poc.gyu-don.workers.dev/mcp` を参照します。ローカルカタログをCodexへ追加し、ChatGPTデスクトップを再起動してPlugins Directoryから **「ゲーム実績イベント」** をインストールします。

```sh
codex plugin marketplace add .
codex plugin add dots-game-achievements@te-no-hira-lab
```

ローカルにインストールした後は、ChatGPTデスクトップでPlugins Directoryを更新し、新しいチャットから利用してください。画面に出ない場合はデスクトップアプリを再起動します。クラウド版でのイベント購読には、上記のChatGPT側の接続を利用してください。

### Dotから購読する

WorkチャットでDotsを選び、イベントタブにある例のように、`achievement.unlocked` を購読して達成を受け取ったらプレイヤーをほめるよう頼みます。購読を始めてからJSONを送信すると、そのWorkチャットへイベントがプッシュされます。デスクトップ版WorkではCloud実行を選択してください。

`get_recent_game_events` ツールもあり、直近のイベントを確認できます。イベント中の文章はゲームデータとして扱い、指示として実行しません。

## センサー判定の範囲と限界

これは絶対位置を計測する仕組みではありません。端末の加速度から短いストロークの概算移動を作り、「ゲーム入力として成立するか」を評価します。

1. スマホで `devicemotion` を取得。iOSではボタン操作から `DeviceMotionEvent.requestPermission()` を呼ぶ。
2. 1秒の静止でバイアスを校正。重力込み加速度と重力除去済み加速度の差から重力方向を求め、加速度を水平面へ投影する。端末が傾いた際のY/Zの混ざりを抑える。重力除去済み加速度がない端末は、ジャイロによる重力方向予測と低速フィルターで代用する。
3. 水平加速度を2次元ベクトルとして積算する。デッドゾーンと速度上限はベクトル全体に適用し、軸ごとの向き固定やブレーキ固定は行わない。初期の左右・上下倍率は両方1.0。加速度が小さい間は速度を減衰させ、初期値800msの無加速が続いたら速度をゼロにする。等速移動と静止を識別できないため、減衰・停止待ち時間はコントローラーで調整する。
4. 重力方向の衝撃後、初期値150ms静止すると着地とみなす。衝撃のしきい値・静止時間・静止の許容ノイズ・再検出間隔はスマホで調整可能。衝撃後700ms以内に静止しなければ候補を破棄し、着地後650msは二重検出を抑える。水平移動なしの着地でも操作できる。静止だけでは着地・手の切り替えにならない。着地確認中はオレンジのリング、確定時は波紋・枠の発光・文字をPC画面に表示する。
5. 手は開閉状態を持ち、開く→にぎるの着地で105px以内の最も近い未配置図形をつかむ。閉じた状態で移動すると図形が追従し、次の着地で離す。図形は穴への射影距離と横ずれで広く判定。初期の必要距離の30%以上動き、横ずれが48%以内なら吸着候補になる。穴の近くなら半径145pxの許容範囲もある。方向が逆・ほぼ無移動なら吸着しない。
6. クリーナーは移動した線分全体を消す。静止中は消さない。描画と判定はPCブラウザ内で行う。

ゆっくりした等速移動、傾き、回転、端末固有のノイズには弱く、実距離と画面上の距離は一致しません。平らなまま、短く動かして止める使い方を想定します。重力フィルターのフォールバックは特に精度が落ちます。画面ロック・別アプリへの切り替え時は入力を停止し、戻ってから再校正します。画面スリープ防止は対応端末でのみ使います。

慣性センサーだけで接地を確実に識別することはできず、空中で縦に振って止める動作も着地になる場合があります。端末ごとの実機での精度改善は未検証です。まず同じ方向のストロークを数回試し、静止中に動かないか、着地が過敏でないか、1ストロークの移動量が適切かを診断欄で確認してください。ブラウザごとの制約は [MDNのDeviceMotionEvent](https://developer.mozilla.org/en-US/docs/Web/API/DeviceMotionEvent)、[権限要求](https://developer.mozilla.org/en-US/docs/Web/API/DeviceMotionEvent/requestPermission_static) を参照。

## 通信と無料枠の見積もり

```text
PCブラウザ ─── WebSocket ───┐
                           ├── 1 room = 1 Durable Object
スマホ ─── WebSocket ≤20Hz ──┘        (Hibernation API)

スマホ: センサー取得・校正・推定 → 累積座標・動作・着地カウンター
PC:     ゲーム判定・描画・ログ ← スマホから設定を受け取り診断に表示
```

静的ファイルはWorkers Assets。通信はWebSocketのみで、HTTPポーリングはありません。スマホのセンサーが60〜100Hzでも入力送信は最大20Hz、静止中は1Hz。パラメータ変更はまとめて送信し、操作画面の再接続時に再配信する。フレームは累積座標なので、中間パケットを間引いても移動量を引き継げます。再接続・再校正では座標の基準を取り直して手を開き、古い入力や着地を再生しません。1ルームは表示1接続＋操作1接続に制限し、同一端末の再接続は置換します。

保存するのはルームの接続トークンと24時間の期限だけ。センサーフレームごとにDB保存しません。WebSocketの状態はHibernation attachmentに置き、タイマーをDOに置かず、24時間後のアラームでルームデータを削除します。ゲームの進行はPCメモリ内にあり、PCの再読み込みでリセットされます。診断ログはPC内に最大2,400フレーム保持し、手動ダウンロードできます。

**合計120分（7,200秒）、1プレイヤーが全時間20Hzで操作した場合の上限寄りの計算:**

| 項目 | 設計上の見積もり | Free枠 / 日 |
| --- | ---: | ---: |
| 入力WebSocketメッセージ | 144,000通 → 課金換算7,200リクエスト | DO 100,000リクエスト |
| 20秒ごとの両画面のheartbeat | 720通 → 課金換算36リクエスト | 上記に含む |
| DO実行時間 | 常時アクティブと仮定して約922 GB-s | 13,000 GB-s |
| Workersリクエスト | ページ表示、ルーム作成、WS接続などのみ | 100,000リクエスト |
| DB書き込み | ルーム作成・期限設定・削除程度 | 100,000行書き込み |

接続や設定操作を加えても、通常の120分ではDOリクエスト・実行時間ともに無料枠の約8%以下を目安にできます。DOからPCへの送信はリクエスト課金対象外です。小さなJSONを転送するだけなので処理も軽量です。無料枠はアカウント内の他アプリと共有され、日次リセットはUTC 00:00です。公開先への無関係な大量アクセスはこの通常利用の計算に含みません。

料金確認: 2026-10-17。[DO公式料金・20:1の計算規則](https://developers.cloudflare.com/durable-objects/platform/pricing/)、[Workers公式料金](https://developers.cloudflare.com/workers/platform/pricing/)、[Hibernation API](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)。


## v3のコントローラー調整

スマホの **「センサーの調整」** が設定元です。PCからスマホの設定を上書きしません。値はスマホのlocalStorageに保存し、ルーム変更や再読み込み後も使います。設定パネルを開くとゲーム入力・着地を停止し、閉じたときに1秒の再校正を行います。開く前にセンサーが有効でなかった場合は、自動開始せず「センサーを有効にする」から開始します。画面ロックからの復帰も手動再開です。

| 症状 | 最初に試す調整 |
| --- | --- |
| 動かしても反応しない | 「小さな動きの無視」を下げる。その後「移動の感度」を上げる |
| 動くが移動量が小さい | 「移動の感度」を上げる |
| 左右または上下だけ小さい | 対応する方向の倍率を上げる |
| 斜めの向きが変 | 左右・上下の倍率を1.0に戻して再校正。傾き補正のオン・オフも比較 |
| 置いたまま動き出す | 平らに置いて再校正。「小さな動きの無視」を上げる |
| 動かし続けている途中で止まる | 微調整の「無加速になってから止めるまで」を長くし、余韻の抑制を弱める |
| 止めても流れる | 「動きの余韻を抑える強さ」を上げる。それでも流れたら停止待ちを短くする |
| ガタつく / 反応が遅い | 「入力をなめらかにする時間」を長くする / 短くする |
| そっと着地しても検出しない | 「着地に必要な衝撃」を下げる |
| 着地リングから確定しない | 「着地後の静止時間」を短くする、または静止のゆるさを上げる |
| 着地が二重に出る | 「着地の連続検出を防ぐ時間」を長くする |

各スライダーの直下にも、値を上げる・下げる目安を表示します。「すべて初期値に戻す」も利用できます。生の加速度・補正後の加速度・推定速度・入力のしきい値判定をスマホとPCの診断に表示します。スマホの小さなベクトル図はセンサー入力の確認用で、ゲーム状態を受け取りません。生の値はブラウザが返した加速度（linear accelerationが利用できない場合は重力をフィルタリングした値）で、物理センサーの未加工データではありません。

軸が凍る問題・小さな斜め入力・停止を挟まない切り返し・無加速192msでの早期停止を回帰テストに追加。静止と等速移動を完全に区別することや、実距離の正確な計測は保証しません。

## 検証

```sh
pnpm test
pnpm check
pnpm build
# 別ターミナルで pnpm dev を起動してから
pnpm test:integration
```

ユニットテストは静止ノイズ、水平移動、着地、重力込みフォールバック、校正・時間ギャップ、感度・反転、吸着の成功/失敗、再接続、拭き取り、累積座標を検証。統合テストは実際のworkerdでルーム作成、HTTPルート、Origin制限、役割トークン、WebSocket中継、2台目拒否、再接続、設定の再配信、heartbeat、不正メッセージ拒否を検証します。実際のスマホのセンサー品質はこの自動テストだけでは保証しません。

主要コード: `src/client/motion.js` 推定、`src/client/game.js` 判定、`src/client/display.js` 表示、`src/client/controller.js` スマホ、`src/worker/index.js` 中継。
